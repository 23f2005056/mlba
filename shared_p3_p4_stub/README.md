# Shared synthetic stub for P3 and P4

These three Parquet files are **fictional test data**, generated by
`make_shared_stub.py`. They are a shared starting point while P1 and P2 prepare
the real files. They contain eight invented 10-digit NPIs and six decision
years (2016-2018 and 2020-2022). Do not report results from this stub as
project findings.

| File | Grain | Columns |
| --- | --- | --- |
| `provider_features.parquet` | NPI, year | `specialty`, `total_payment`, `beneficiaries`, `services`, `payment_per_beneficiary`, `services_per_beneficiary` |
| `candidate_pool.parquet` | NPI, year | Eligible audit candidates only |
| `labels.parquet` | NPI, year | `label_scenario_a` (primary), `label_scenario_b` (robustness) |

`NPI` is a string and `year` is an integer in every file. The candidate pool
and labels have identical keys. Features also include provider-years that are
not eligible, so **join to the candidate pool before scoring or evaluating**.

Labels indicate an exclusion in years `year + 1` through `year + 3`.
Scenario B includes Scenario A plus one synthetic B-only event. A provider
excluded in 2019 is absent from all later candidate pools; another excluded
in 2021 is absent from 2021 and 2022. The synthetic 2024 and 2025 exclusions
exercise the 2021-2022 test window. These dates are encoded in the generator
solely to make consistent labels; they are not real LEIE observations.

For predictions, P3 and P4 should agree on a fourth file with columns
`NPI`, `year`, `approach`, and numeric `score`. Use one row per eligible
NPI-year-approach and define **higher score as higher audit priority**.
P3 should score the entire eligible evaluation pool for each approach or
report missing scores. The approach names and any extra columns must be
agreed before integration. The project work plan freezes the keys, but not
the non-key column names proposed in this stub.

Example read:

```python
import pandas as pd

features = pd.read_parquet("stubs/provider_features.parquet")
candidates = pd.read_parquet("stubs/candidate_pool.parquet")
labels = pd.read_parquet("stubs/labels.parquet")
eligible = candidates.merge(features, on=["NPI", "year"], validate="one_to_one")
eligible = eligible.merge(labels, on=["NPI", "year"], validate="one_to_one")
```

The real three-year label windows must be mature at the decision date before
they can be used for model training. For example, a model making a decision
at the end of 2021 can use training rows through 2018, whose windows close
by the end of 2021.
